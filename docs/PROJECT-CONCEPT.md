# Концепция проекта

## 1. Статус и назначение

«Практическое руководство для священнослужителя» — самостоятельный **справочно-учебный проект**, созданный в рамках изучения одноимённого курса БПДС.

Проект не заявляется как официальный ресурс БПДС. Его задачи:

- подготовка к зачёту по курсу;
- сохранение канонических формулировок экзаменационных билетов;
- объединение повторяющихся вопросов в нормализованные темы;
- сопоставление одной темы с несколькими учебными и справочными источниками;
- быстрый переход от краткого ответа к первоисточнику;
- постепенное формирование удобного электронного учебного справочника.

## 2. Каноническая модель

Главный объект системы — не книга, а **экзаменационный вопрос / нормализованная тема**.

Базовая связь:

`билет → экзаменационный вопрос → нормализованная тема → источники → ответ / фрагмент первоисточника`

Текущая база:

- 30 билетов;
- 180 экзаменационных позиций;
- 171 нормализованная тема.

Количество источников не является архитектурным ограничением.

## 3. Библиотека источников

Сейчас подключены:

1. протоиерей Геннадий Нефёдов — «Таинства и обряды Православной Церкви»;
2. протоиерей Николай Сильченков — «Практическое руководство при совершении приходских треб».

В план расширения приняты:

3. Булгаков С.В. — «Настольная книга для священно-церковно-служителей»;
4. Дебольский Г.С., прот. — «Православная Церковь в ее Таинствах, богослужении, Обрядах и Требах»;
5. Остапов А.Д., прот. — «Пастырская эстетика»;
6. Кураев А., диак. — «Традиция, Догмат, Обряд : апологетические очерки».

После анализа книга может выполнять одну или несколько ролей:

- **основной учебный источник** — системно покрывает значительную часть курса;
- **справочный источник** — даёт нормы, подробности и варианты практики;
- **тематический источник** — полезен для ограниченного круга тем;
- **дополнительный богословский / исторический источник** — углубляет понимание, но не обязан давать прямой экзаменационный ответ.

Роль не назначается заранее только по названию книги; она определяется после анализа фактического содержания.

## 4. Принцип неполного покрытия

Новая книга **не обязана иметь ответ на все 171 темы**.

Если источник содержательно полезен только для части вопросов, индексируются и показываются именно эти связи. Искусственные пустые ответы для остальных тем не создаются только ради симметрии данных.

Это позволяет масштабировать библиотеку без перегрузки интерфейса и без ложного впечатления, что все книги равноценны для каждого вопроса.

## 5. Полнота материала

Внутри системы сохраняется техническая шкала `rel_1…rel_5`.

Пользователь видит только человеческую шкалу:

- `■■■■■` — полный ответ;
- `■■■■□` — почти полный;
- `■■■□□` — частичный;
- `■■□□□` — отдельные сведения;
- `■□□□□` — прямого ответа нет.

Правила слабого покрытия:

- **уровень 2 / `■■□□□`** — показываются сами полезные сведения по существу вопроса; упоминания «в учебнике…», «учебник даёт лишь…», «полного ответа нет…» убираются;
- **уровень 1 / `■□□□□`** — содержательный ответ не достраивается общими знаниями; допустима краткая формула «Прямого ответа в этом источнике нет.»

## 6. Пользовательская модель при росте библиотеки

При шести и более книгах нельзя просто выводить шесть одинаковых больших кнопок у каждого вопроса.

Целевой принцип:

- вопрос / тема остаётся визуально главным;
- наиболее полезные источники показываются первыми;
- дополнительные источники раскрываются компактно;
- источник без содержательно значимого материала может не показываться в списке темы;
- полнота материала помогает ранжировать и группировать источники, но не подменяет содержательную проверку.

Перспективное представление:

**Основные ответы**
- Нефёдов `■■■■■`
- Сильченков `■■■■□`

**Другие источники — N ▾**

Точный интерфейс проектируется отдельно перед реализацией.

## 7. Развитие сущности «Тема»

171 нормализованная тема постепенно должна стать пользовательским учебным объектом, а не только техническим идентификатором.

Перспективная страница темы может объединять:

- название темы;
- исходные формулировки и номера билетов;
- краткий учебный ответ;
- список источников с полнотой;
- переходы к соответствующим фрагментам книг;
- связанные темы.

Билеты при этом сохраняются как экзаменационный режим, а темы образуют справочно-учебный слой.

## 8. Библиотека

При росте числа книг должен появиться самостоятельный библиотечный слой.

Для каждой книги:

- автор;
- название;
- роль в проекте;
- «Читать»;
- «Скачать»;
- связанные экзаменационные темы;
- при необходимости — сведения о покрытии курса.

Длинный библиографический список не должен перегружать шапку главной страницы.

## 9. Поиск

Поиск развивается в двух разных направлениях.

### 9.1. Поиск по экзаменационным вопросам и темам

Основной учебный поиск.

Принципы:

- один результат = один экзаменационный вопрос / тема;
- приоритет точных совпадений вопроса и темы;
- затем совпадения по связанным источникам;
- поддержка словоформ, разумной устойчивости к опечаткам и контролируемых синонимов;
- короткий фрагмент объясняет, почему результат найден.

### 9.2. Поиск по полным текстам источников

Отдельный справочный режим.

Он отвечает на другую задачу: найти нужное место непосредственно в книгах, даже если оно не связано с отдельным экзаменационным вопросом.

Эти два поиска не должны смешиваться в одну непонятную выдачу.

## 10. Конвейер подключения новой книги

Каждый новый источник проходит одинаковый путь:

1. исходный файл книги;
2. техническая проверка и нормализация;
3. индекс структуры и оглавления;
4. полнотекстовый корпус;
5. сопоставление с 171 темой;
6. первичная оценка полноты;
7. определение фактической роли и охвата источника;
8. ручная содержательная проверка;
9. формирование пользовательских ответов / фрагментов;
10. подключение к ридеру, поиску и библиотеке.

Сначала анализируется книга, затем принимается решение, какие темы она должна обслуживать.

## 11. Неизменяемые принципы

- Не подменять отсутствующий материал общими знаниями.
- Не менять исходные экзаменационные формулировки без отдельного решения.
- Хранить независимость источников.
- Различать полноту источника и пользовательскую оценку качества ответа.
- Давать возможность перейти от краткого ответа к первоисточнику.
- Не перегружать пользователя техническими идентификаторами.
- Масштабировать систему через тему и библиотеку, а не через механическое размножение кнопок учебников.
