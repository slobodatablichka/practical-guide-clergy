# Система пользовательских оценок и комментариев

## Назначение

Собирать структурированную обратную связь по каждому конкретному ответу для последующего анализа и редакции справочника.

Отзыв относится к паре:

`topic_id + book_id`

То есть ответ по Нефёдову и ответ по Сильченкову на один и тот же вопрос оцениваются независимо.

## Пользовательский интерфейс

После открытия ответа рядом с ним располагается компактный блок оценки.

При первом использовании:
- поле **«Ваше имя»** — обязательно;
- поле **«Оценка ответа»** — 1–5;
- поле **«Комментарий»** — необязательно.

После первого сохранения имени поле имени скрывается. Имя хранится в локальном хранилище браузера. Должна быть доступна ненавязчивая команда **«Сменить имя»**.

Если пользователь ввёл только имя, оно сохраняется только в браузере; запись в общую таблицу не создаётся.

Если поставлена оценка, создаётся или обновляется запись. Комментарий может быть добавлен сразу или позднее.

Одновременно пользователь видит различие:
- `rel_1…rel_5` — релевантность материала учебника вопросу;
- пользовательская оценка 1–5 — качество и полезность показанного ответа.

## Правило одной записи

Для сочетания:

`user_id + topic_id + book_id`

существует одна актуальная запись. Повторная оценка обновляет существующую запись, а не создаёт новый голос.

## Таблица answer_feedback

Поля:

- `user_id` — технический UUID посетителя;
- `display_name` — имя/псевдоним;
- `topic_id` — постоянный идентификатор темы;
- `book_id` — `nefedov` или `silchenkov`;
- `question` — текст вопроса на момент оценки;
- `source_rel` — текущая оценка релевантности источника;
- `rating` — пользовательская оценка 1–5;
- `comment` — необязательный комментарий;
- `answer_revision` — версия/hash текста оценённого ответа;
- `view` — `tickets`, `book` или `search`;
- `ticket` — номер билета, если применимо;
- `position` — позиция вопроса в билете, если применимо;
- `created_at` — время первой записи;
- `updated_at` — время последнего изменения.

Уникальный ключ:

`user_id, topic_id, book_id`

## Хранилище и безопасность

Планируемое хранилище — PostgreSQL/Supabase.

Требования:
- публичный сайт не получает административных ключей;
- посетитель может создавать и изменять только собственные отзывы;
- общая таблица отзывов не доступна посетителям на чтение;
- владелец проекта может выгружать данные в CSV/JSON для анализа;
- Row Level Security включена.

## Реализация

- Supabase project: `practical-guide-clergy`;
- region: `eu-north-1`;
- table: `public.answer_feedback`;
- anonymous sign-ins: enabled;
- RLS: enabled; посетитель читает и изменяет только собственные строки;
- канонические `topic_id` ограничены реестром `public.feedback_topics` из 171 темы;
- комментарий ограничен 2000 знаками;
- клиент использует только publishable key; административные/secret keys на сайт не передаются;
- браузерная библиотека Supabase зафиксирована на конкретной версии.

## Статус

Backend подключён. Форма оценивания встроена в сайт. Требуется один пользовательский тест на опубликованной странице с последующей проверкой записи в базе.
